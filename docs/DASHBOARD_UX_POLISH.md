# Dashboard UX Polish Notes

## 中文界面设计原则

- 默认界面使用简体中文，减少个人用户首次上手成本。
- 保持 API 与后端字段英文，便于脚本、日志与历史兼容。
- 强调“是否影响代理可用性”，避免把未配置项误报为故障。

## 风险展示规则

- 活跃风险（仅显示 warning / degraded / critical）：
  - 包含 `vps_system`、`proxy_core`、`xui_panel`、`proxy_ports`、`traffic`、`domain_dns`、`tls_certificate` 中的告警项。
- 未配置可选检查（单独模块展示）：
  - 域名 / DNS：未配置
  - TLS 证书：未配置

这样可以确保用户不会把可选模块未启用误解为即时风险。

## 顶部运行状态条

- 在顶部显示：
  - 运行模式（本地只读）
  - 绑定地址（默认 `127.0.0.1:3001`）
  - 访问方式（SSH Tunnel）
  - 无公网暴露

信息来自后端 `/api/meta`，未来可直接扩展更多运行信息。

## 代理链路总览

新增“代理链路”区块，帮助用户快速理解依赖关系：

1. VPS 健康
2. 代理核心运行
3. 3X-UI 面板可达
4. 代理端口开放

健康时给出“代理链路正常”结论，异常时给出“代理链路存在风险”提示并引导查看诊断建议。

## 诊断上移

- 在总体状态附近增加“诊断摘要”区块，用于快速判断有无关键诊断项。
- 健康时显示“未发现需要处理的诊断问题。当前无需执行排查命令。”并降低占用。
- 异常时展示最重要诊断项与建议第一检查项。
- 完整“诊断建议”区块保留在页面后部，保持可读性。

## 未配置文案与中性样式

未配置项使用 `未配置` 与中性样式，不使用红黄绿色提示。  
这样可避免在“未启用 Domain / TLS 时”看到误导性的危险状态。

## 截图建议

- 展示 dashboard 时建议裁掉浏览器顶部地址栏/开发者工具。
- 截图中避免出现真实 IP、真实域名、token、UUID、面板密码等敏感信息。
